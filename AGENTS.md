## Архитектура

- Закреплённые версии — package.json/package-lock.json, npm — единственный менеджер пакетов. Проверяй API установленной major-версии; старые Phaser 3 примеры не доказывают совместимость с Phaser 4.
- `src/domain`: чистое TS состояние + действие → состояние/события; без React, Phaser, DOM, SDK, сети и хранилища. `src/game`: сцена и адаптация ввода. `src/app`: доступный DOM-интерфейс. `src/platform`: только публичный SDK.
- Одна принадлежащая viewport инстанция Phaser.Game; освобождай listeners, таймеры, ресурсы и незавершённую загрузку при уходе. Не обновляй React каждый кадр. Физический движок для пошагового поля не нужен по умолчанию.
- Читаемые слова и объяснения — отдельный текстовый слой; не встраивать текст в изображения. Передний план не перекрывает учебные объекты и ввод. Масштабирование через Phaser Scale Manager, проверка от 360 px.
- Сырые внешние данные имеют тип unknown и проверяются до использования. Не скрывай ошибки через any, подавления TypeScript или отключение lint.
- Клавиатура и кнопки касания отправляют одни действия. Пауза платформы, пользователя и скрытой вкладки независимы; снятие одной не снимает остальные. Не перехватывай ввод вне игрового viewport.

## Учебные и платформенные инварианты

- Игра — учебная часть DayEnglish, формирующая грамматическую базу. Новое правило вводить через название/термин с простым объяснением, смысл, условия, форму, пример и границы; далее показ → самостоятельное применение → перенос → повтор. Доступное в журнале объяснение не заменять подсказкой движения. Направляемую карту не считать доказательством усвоения.
- Разделять форму, уместность в контексте и результат в мире. a/an зависит от звука; the — от однозначности для участников, не от номера упоминания. a не означает «создать», the не означает универсальное «выбрать».
- Контент и допустимые альтернативы — проверенные локальные данные. Онлайн-ИИ, сеть, подписка и звук не определяют правильность ответа.
- Undo восстанавливает мир и контекст, но не стирает историю попыток, раскрытие решения и сохранённые пользователем слова. Нет жизней и штрафов за перевод.
- Одно SDK-соединение на запуск, дождаться ready, проверять capabilities. На paused/closed остановить ввод, анимацию и звук. На closed больше не отправлять запросы.
- Сохранения принадлежат DayEnglish: версионированный JSON, последовательные CAS-записи и стабильный operationId при повторе. Не перезаписывать неизвестную схему. Словарь/перевод — через SDK; FSRS не изменять по факту победы. Подробности в [INTEGRATION](docs/INTEGRATION.md).

## Навыки и работа

Навыки находятся в `.agents/skills/`; читать только релевантные, не загружать каталог целиком. Источники и адаптации — [SKILLS](docs/SKILLS.md).

- `dayenglish-studio`: поэтапное развитие игры по адаптированному studioigor; существующие решения и текущий объём имеют приоритет.
- `ax-joint-design` + `ax-ux-ui`: новые/существенно изменённые UX/UI, AIUX knowledge и реальные экраны Gummble; это выбранная владельцем основа из AIUXArchitect. При дизайне Gummble использовать фактически, не заменять описанием сервиса. Обычные CSS-правки и техническая сцена не требуют полного UX-процесса.
- В `ax-ux-ui` добавлены адаптированные практики Genex: композиция/типографика/состояния и отдельный режим рефакторинга UI. Для рефакторинга без нового дизайн-решения повторный Gummble/AIUX research не нужен; сохранять состояние комнаты, фокус, независимые паузы и SDK-контракты. Варианты и отдельная галерея стресс-состояний — по запросу. [Источники и границы](docs/GENEX_SKILLS_REVIEW.md).
- `phaser-core`: Phaser 4, загрузка, сцены и lifecycle. Для этого проекта UI живёт в React, тесты — Vitest/Playwright, глобальный window.game не добавлять в production.
- `vercel-react-best-practices`: релевантные правила React SPA. Не переносить Next.js/RSC/server actions или next/dynamic в Vite.
- `vitest`: детерминированные проверки важных правил и границ.
- `dayenglish-level-review`: методическая проверка карт и условий.
- `dayenglish-learning-copy`: естественные диалоги и понятные задания, объяснения и обратная связь; применять вместе с методической проверкой. Сохранять роли, примеры и границы правила; озвученные тексты не менять при работе только с неозвученным. [Исследование и адаптация](docs/LEARNING_COPY_RESEARCH.md).
- `dayenglish-art-pipeline`: будущая генерация изображений, планов и анимаций через доступный Codex imagegen, их проверка и происхождение.
- `dayenglish-game-feel`: читаемая обратная связь на действия и удобный ввод без изменения учебной логики.
- `dayenglish-voice-pipeline`: кастинг персонажей и подготовка готовых аудиоассетов через API или локальный Qwen; отдельные настройки речи и учебного произношения. Кот, Марта и Тик подключены; различать выбранные эталоны, сгенерированные записи и прослушанную владельцем озвучку.

Выполняй [DEVELOPMENT](docs/DEVELOPMENT.md): краткий план → реализация → соответствующие проверки → самопроверка → исправления. Обновляй MASTER_PLAN по фактам. Независимые агенты — только когда явно запрошены. Коммит, push, публикация и изменения внешних сервисов — по поручению; bootstrap не авторизует релиз.

`npm run check` проверяет навыки, lint, формат, unit tests, TypeScript и сборку. `npm run test:e2e` проверяет браузер. UI/сцену дополнительно осмотреть визуально; browser emulation не доказывает работу Android runtime или обучение людей.
