# Combine knowledge and visual references into one design

Adapted from the owner's AIUXArchitect skill. Read [game rules](../../../AGENTS.md) and [GDD](../../../docs/GDD.md). Preserve the accepted [Фонарь и мох direction](../../../docs/ART_DIRECTION.md). Gummble is reference evidence; Codex authors the resulting UI.

Follow the target product rules and [ax-ux-ui](../ax-ux-ui/SKILL.md).
A combined toolchain is a design method, not evidence that its result beats either source.
For behavior-preserving UI code refactoring without a new design decision, use
ax-ux-ui's refactoring mode; do not run a new Gummble/AIUX study merely to move code.

## Protect the useful baseline

Read the chosen prototype and actual product behavior. Preserve the selected
navigation, visual character and successful interactions. Save a derivative of
frozen comparison outputs. State the user task, concrete improvement and acceptance
before adding controls. Without an established usability failure, call the change
an exploratory proposal.

## Resolve the decisions that matter

Use AIUX to inspect applicable mechanisms, exact claims and limits through the
[knowledge-to-decision workflow](../ax-ux-ui/references/knowledge-to-decision.md).
Use Gummble MCP to discover screens/flows and inspect actual images. Send hosted
research generic public queries; keep private product data local.

Discover available tools first. If AIUX is absent from this client but its local
server is available, the existing SDK stdio route in the
[tool guide](../../../docs/DESIGN_TOOLS.md) may provide real retrieval. Record that
route and inspect delivered images. If a requested source cannot be used, report
the specific gap and continue independent work without implying both contributed.

Search for the uncertain transition. Read ordered flow metadata and enough actual
screens to understand relevant entry/action/result/return states. Mark uninspected
transitions unknown. Stop when important decisions have usable grounds; library
size and reference count are not goals.

For HUD, dialogue, chapter maps and cinematic transitions, supplement app references
with actual game footage or official gameplay material when the decision depends
on play space, timing or interruption. Record the inspected scene/time and distinguish
what is visible from inferred input or behavior. Gummble alone does not establish
that a mobile app pattern works during play. Use original game art, not copied assets.

For consequential choices keep a short note outside the UI: product constraint,
inspected claim/screen, chosen mechanism, alternative or rejection, observable
check. AIUX recommendations are conditional: adapt or reject them when they
complicate the task or conflict with the product. Attractive references do not
override progress, persistence, accessibility or content rules. Do not copy vendor
assets into the prototype or ingest the Gummble library.

## Implement a coherent flow

Choose one hierarchy and visual direction. Prefer an obvious primary action,
useful feedback and a complete next step over accumulating features from sources.
Keep source names and research bookkeeping in the decision note. Use synthetic
content and label simulated capabilities. A prototype request does not authorize
production work.

Apply [the development workflow](../../../docs/DEVELOPMENT.md): plan,
implementation, meaningful tests, browser walkthrough and closing review. Check
the full requested journey, error/retry, interruption/return, completion, narrow
screens and keyboard focus where applicable. Compare with the chosen baseline
for regressions in clarity, density and visual character.

Deliver the artifact, changes, actual source use, checks and material limits.
Owner preference and technical checks remain separate. A comparison or independent
agent requires its own requested scope; this skill does not create either.
